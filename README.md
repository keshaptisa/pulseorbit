# Пульс Орбиты

Исследовательский прототип сравнения временных окон внекорабельной деятельности на МКС.

## Реализовано

- Текущий режим: NOAA SWPC alerts и CelesTrak ISS OMM/TLE.
- SGP4-траектория и цилиндрическая модель орбитальной тени.
- Исторический анализ NOAA NCEI daily solar event reports за май-июнь 2024.
- Строгий cutoff-контракт для replay: записи после cutoff исключаются.
- Сравнение окон одинаковой длительности и отказ от рекомендации при критически неизвестных данных.
- Кеш исходных ответов, SHA-256, статусы `fresh`, `stale`, `unavailable`.
- Сохранение расчёта по стабильному `result_id` и повторное получение через API.
- JSON-экспорт с параметрами, источниками, версией алгоритма и доказательствами.
- CSV-экспорт всех сравниваемых окон и видимое сравнение с исходным baseline.
- Локальный импорт исторических TLE ISS и выбор набора по эпохе.
- Ограничение непрерывного освещения задаётся явно; без него тень не повышает риск.
- Принудительное обновление источников, прямые ссылки на доказательства и сохранённый эксперимент event/control.
- Матрица факторов по всем сравниваемым окнам и последующая проверка replay по независимому наблюдательному архиву.
- Три предпочтительных варианта с объяснением, почему конкретное окно лучше или хуже ближайшей альтернативы.
- Визуальная шкала света и модельной тени по всей области поиска.
- Обработка дублей и отмен NOAA, SHA-256 исходной записи и атомарная запись кеша/результатов.
- Официальный NOAA SWPC 3-day forecast: Kp по трёхчасовым интервалам, вероятность S1+ и R3+.
- Операторские статусы и обязательное действие без ложной формулировки «ВКД безопасна».
- Раздельные домены риска: радиация, связь/навигация, освещённость и полнота данных.
- Формальный checklist решения: профиль операции, версия политики, актуальная дозиметрия и порог организации.

Текущие NOAA alerts и OMM-элементы ISS загружаются автоматически и кешируются на 2 часа. Если источник недоступен, используется только ранее сохранённый ответ с отметкой `stale`; при полном отсутствии источника все зависящие от него факторы получают статус `нет данных`, а рекомендация не выдаётся. Сервис никогда не подставляет синтетические значения вместо измерений и прогнозов. Ни один из этих режимов не является разрешением на реальную ВКД.

## Операторская интерпретация

Система разделяет наблюдаемые alerts и официальный трёхсуточный прогноз NOAA. Уровни S3-S5 переводятся в статус обязательного радиационного пересмотра, поскольку NOAA указывает опасность для EVA. Уровни G/R показываются отдельно как риски для связи, навигации и эксплуатации аппарата. Они не суммируются с радиацией в физическую вероятность травмы.

Статус `CONDITIONAL` означает только возможность продолжить планирование. Для реального допуска нужны бортовая дозиметрия, профиль конкретной работы и решение уполномоченного специалиста. `HOLD_DATA` запрещает рекомендацию при отсутствии критичных данных.

Оператор может ввести телеметрию дозиметра и утверждённый организацией порог. Запись старше 30 минут, неполный профиль или отсутствующая версия политики блокируют финализацию решения. Достижение заданного порога выдаёт отдельный `HOLD_DOSIMETRY`. Порог не встроен в продукт как универсальная медицинская норма: его владельцем остаётся организация, утвердившая полётную политику.

Для вероятностных прогнозов используются прозрачные демонстрационные границы: менее 25% — мониторинг, 25–49% — проверка, 50% и выше — действие. Это настраиваемая политика прототипа, а не норматив NASA.

## Запуск

```powershell
python -m uvicorn app.main:app --reload
```

Открыть `http://127.0.0.1:8000`. Документация API доступна на `http://127.0.0.1:8000/docs`.

JSON, который скачивает интерфейс: `GET /api/results/{result_id}/result.json`. Полный пакет результата: `GET /api/results/{result_id}/export`. CSV окон: `GET /api/results/{result_id}/windows.csv`. Все три выгрузки строятся из одного сохранённого результата. Сравнение с baseline: `GET /api/results/{result_id}/baseline`.

## Docker

```powershell
docker compose up --build
```

Для публикации подготовлен `render.yaml`. После подключения репозитория Render использует `Dockerfile` и проверяет `/api/health`. Сам факт наличия конфигурации не означает, что публичный стенд уже развёрнут.

Кеш и результаты сохраняются в `data/cache` и `data/results`; архивные данные монтируются из `data/archive` только для чтения.

## Ограничения

- Полный прогноз из прошлого требует датированных прогностических выпусков NOAA, а не итогового daily event report.
- Архив содержит 59 реальных NOAA daypre-файлов за май-июнь 2024; выпуски за 1 и 18 июня отсутствуют в первичном архиве и не заполняются искусственно.
- Исторический разбор использует 8785 реальных координат ISS из NASA GSFC SSCWeb в GSE с шагом 10 минут и покрывает 1 мая - 1 июля 2024. Это ретроспективный архив, поэтому он не используется в строгом replay.
- Строгий replay орбиты по всему периоду требует `GP_HISTORY` Space-Track с полем `CREATION_DATE`; без него система не подменяет прошлое ретроспективными координатами NASA.
- Оценка освещённости не учитывает полутень и геометрию конкретного рабочего места.
- Сервис не рассчитывает дозу человека и не выдаёт разрешение на реальную ВКД.

## Почему освещённость выбрана вторым механизмом

Это осознанный инженерный компромисс: SGP4 и аналитическая модель Солнца дают простой, воспроизводимый и проверяемый расчёт на ближайшие часы. Освещённость влияет на видимость и может стать рабочим ограничением конкретной ВКД, но модель не подменяет расчёт локального терморежима или конфигурации рабочего места. Поэтому тень без явного требования непрерывного света остаётся информационным фактором.

Собственная расчётная часть шестичасового горизонта — распространение орбиты и интервалы тени. Космическая погода использует внешний прогноз NOAA, который система интерпретирует, но не выдаёт за собственную физическую модель.

## Источники

| Источник | Величины | Время и обновление | Ограничения |
|---|---|---|---|
| NOAA SWPC alerts | сообщения и шкалы S/G/R | оперативная лента, кеш 2 часа | шкалы описывают разные механизмы; сообщение не равно дозе |
| NOAA SWPC 3-day forecast | Kp, вероятность S1+ и R3+ | официальный прогноз на три суток, кеш 2 часа | вероятности относятся к событию, а не к индивидуальному исходу |
| NOAA NCEI daypre | трёхсуточная вероятность протонного события | время `Issued`, даты прогноза | суточная вероятность, не точное время события |
| NOAA NCEI solar event report | времена XRA-событий | итоговый суточный архив | только ретроспективный индикатор, не replay |
| CelesTrak GP OMM/TLE | элементы орбиты МКС, эпоха | оперативно, кеш 2 часа | точность снижается с возрастом элементов |
| Wayback CelesTrak snapshots | исторические TLE и время захвата | четыре доступных снимка начала мая | неполное покрытие; TLE старше 3 суток не используется |

Воспроизводимый эксперимент запускается командой `python scripts/run_experiments.py`. Инструкция для проверки жюри находится в `docs/JURY_GUIDE.md`.

Валидация на 58 суточных прогнозах и последующих наблюдениях описана в `docs/VALIDATION.md`. При пороге 50% сохранённый результат содержит TP=7, FP=3, FN=0, TN=48, F1=0.824 и Brier score 0.0574. Это проверка прогнозного сигнала, а не риска травмы.

Настройки кеша, сетевого таймаута, возраста исторического TLE, вероятностных границ и URL источников задаются переменными `EVA_CACHE_TTL_HOURS`, `EVA_REQUEST_TIMEOUT_SECONDS`, `EVA_HISTORICAL_TLE_MAX_AGE_DAYS`, `EVA_FORECAST_WATCH_PERCENT`, `EVA_PROTON_THRESHOLD_PERCENT`, `EVA_NOAA_ALERTS_URL`, `EVA_NOAA_FORECAST_URL`, `EVA_CELESTRAK_OMM_URL`, `EVA_CELESTRAK_TLE_URL`.
Числовые значения приводятся к типам при загрузке конфигурации; некорректное значение завершает запуск с явной ошибкой вместо скрытой подстановки.

Статусы факторов различаются намеренно: `не выявлено` означает отсутствие совпадения в пределах конкретного продукта, `информационно` — рассчитанное условие, которое не участвует в выборе без ограничения работ, `нет данных` — невозможность оценки. Ни один из этих статусов сам по себе не означает разрешение на ВКД.
