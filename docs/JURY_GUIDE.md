# Проверка решения жюри

## Быстрый сценарий

1. Запустить `python -m uvicorn app.main:app --reload` и открыть `http://127.0.0.1:8000`.
2. В текущем режиме проверить пересчёт при изменении начала, длительности и диапазона поиска.
3. Включить «Требуется непрерывное освещение»: только после этого орбитальная тень становится ограничением выбора.
4. Отключить NOAA: сервис должен показать неизвестный критичный фактор и отказаться от рекомендации.
5. Включить принудительное обновление: статус должен показать получение новых данных.
6. Выбрать replay, дату `10.05.2024 00:00 UTC`, cutoff `09.05.2024 23:00 UTC`: используется только выпуск NOAA с `Issued <= cutoff`.
7. Скачать ZIP и проверить `report.html`, `result.json`, `windows.csv`, `manifest.json`.
8. Показать блок трёх предпочтительных вариантов, строку «почему хуже» в таблице и шкалу света и тени.

При равноценных вариантах сервис не назначает предпочтительное окно: первая строка отмечает только выбранный пользователем вариант для просмотра доказательств. Метка `не выявлено` ограничена охватом конкретного NOAA-продукта, а орбитальная тень без рабочего ограничения помечается как `информационно`.

## Проверяемые артефакты

- `data/validation/experiment_summary.json` — сохранённый эксперимент события и контроля.
- `data/archive/manifest.json` — URL и SHA-256 архивных файлов.
- `docs/RESEARCH.md` — механизмы, правила и границы интерпретации.
- `/api/results/{id}` — сохранённый расчёт; `/export` — воспроизводимый пакет.
- `/api/results/{id}/result.json` — тот же сохранённый расчёт, который скачивает кнопка JSON; браузер не пересобирает его самостоятельно.

## Честные ограничения

- Протонная вероятность NOAA — прокси внешней обстановки, не доза космонавта.
- XRA в historical — ретроспективный индикатор вспышек, не взаимозаменяемый с протонным прогнозом replay.
- Тень влияет на рекомендацию только при явном ограничении непрерывного освещения.
- Исторический разбор использует реальные координаты ISS из NASA GSFC SSCWeb за весь период 1 мая - 1 июля 2024; в строгом replay этот архив не применяется, поскольку не доказывает момент публикации каждой координаты. Современная орбита историческую не заменяет никогда.

## Позиционирование решения

- Выбран один полноценный web-сценарий. Telegram-интерфейс не дублируется, чтобы не расходовать время на два менее цельных пользовательских пути.
- Освещённость выбрана как проверяемый расчёт команды на шестичасовом горизонте. Она важна для видимости и рабочих ограничений, но не подменяет тепловую модель.
- Прогноз космической погоды предоставляет NOAA. Команда выполняет временную фильтрацию, интерпретацию, сравнение окон и проверку по последующим наблюдениям.
- TEME-векторы SGP4 не выдаются за координаты ITRF: интерфейс показывает интервалы тени, для которых такое преобразование не требуется.

## Два обязательных демонстрационных случая

1. Перенос ничего не улучшает: несколько окон получают одинаковый минимальный индекс, автоматический выбор не выполняется.
2. Данных недостаточно: отключение NOAA даёт `нет данных`, а не пустой экран и не ложный благоприятный статус.

## Проверка отсутствия заглушек

- При `EVA_LIVE_DATA=0` источники получают статус `unavailable`, факторы уходят в `нет данных`, рекомендация не выдаётся: значения не подставляются.
- `python scripts/run_experiments.py` пересчитывает `data/validation/experiment_summary.json` из сохранённых выпусков NOAA и воспроизводит опубликованные цифры.
- Выпуски daypre за 01.06.2024 и 18.06.2024 отсутствуют, потому что NOAA отдаёт на них HTTP 404; пропуски не заполняются.
- Сутки трёхсуточного прогноза NOAA датируются по шапке таблицы, а не по строке-диапазону, поэтому колонка вторых суток не приписывается третьим.
